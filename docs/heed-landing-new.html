You lead. heed follows through.

To heed is to pay attention. heed pays attention to everything your agents do, and everything that happens to their work after, so yours only goes where it’s needed.

Start work

Have a thought? Start typing.

⌃⌥Space from any app, or o in heed. Say what you want; heed picks the repo, the worktree, the branch and the agent. Quick calls like these run on a small local model on your Mac, where it has one, and heed shows you why it chose what it did. Change anything with one key, or just press enter.

Sessions

A great multiplexer, to begin with.

Every agent you use, each in its own terminal and worktree. heed knows what each is doing and brings you to the one that needs you. With zmx, terminals outlive heed itself, and agents on your other machines, over ssh or your tailnet, sit in the same window.

Keyboard first and mouse friendly. If you’ve ever typed :wq to quit something, you’re already home.

The noise

heed handles the noise.

Every PR your agents open, heed keeps an eye on. Reviews, feedback and failing checks go back to the agent that wrote the code, until it’s green, and merged where you’ve turned merging on. You see what heed did, not everything it had to do.

When an agent needs a yes, it’s one key. When a PR needs a step, heed takes it, beside your session, never in it.

Bigger work

We know you have a favourite harness. Let heed put the others to work.

Plan bigger work with a panel that speaks its mind, the Skeptic included. heed shares it out across every agent you have and brings it home.

A second opinion when it counts: quiet, until there’s something worth a look.

Memory

heed remembers, so you don’t have to.

Every PR, every decision, every piece of work, kept as a short summary in a memory for each org. Claude and Codex get it back as context, and you get it back as answers.

Mindmap

What heed learnt about your work, per org, fed back to Claude and Codex. Orgs never mix.

Standups that write themselves

Your own questions, answered on the days you choose, ready to paste.

Insights

What it all added up to. History: every piece of work and how it went.

Full observability

Claude Code’s and Codex’s own OpenTelemetry, received on your Mac: where time goes, what each model costs, every session’s trace.

It’s all still yours.

  • Your agents, your logins, no API key.
  • Agents keep their own transcripts, and heed stores none of them.
  • Hooks passed per run: your agent config is never edited.
  • Memories never cross orgs.
  • When heed passes your telemetry on to a collector of yours, it says so in a banner, and one key stops it.

Questions, answered briefly

Does it work with my agent?

Claude, Codex, Cursor, pi, opencode and gemini are built in. Anything else you can run in a terminal works as a custom agent, with its states read from output patterns.

Does it replace my agent?

No, heed runs the one you have.

How does it know when an agent is blocked?

Through each agent’s hooks, where it has them, using a small helper command the agent calls. Where it has none, heed watches the terminal and marks that state as a guess.

Will it merge my PRs on its own?

Only where you turn merging on, per PR, repo or org; it is off by default. Watching is on by default because it only reads from GitHub.

Do I have to use the keyboard?

No, but you will want to. Everything is a key, there is a help overlay on ? in every mode, and the mouse works too: every command is in the menu bar and the right-click menus, with its key beside it.
