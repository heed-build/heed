01Start

Have a thought? Start typing.

Press ⌃⌥Space in any app, or o in heed, and say what you want. heed picks the repo, the worktree, the branch and the agent, and shows why it picked each one. Where your Mac has a small local model, that model makes these quick calls. Change any pick with one key, or press enter to start.

02Sessions

A great multiplexer, to begin with.

Every agent runs in its own real Ghostty terminal, in its own worktree. heed knows what each agent is doing and takes you to the agent that needs you. With zmx, the terminals keep running when heed quits. Agents on your other machines, reached over ssh or your tailnet, appear in the same window.

Keyboard first, and the mouse works too. If you’ve ever typed :wq to quit something, you’re already home.

03Autopilot

heed handles the noise.

Autopilot gets PRs green, merges them by your rules, takes each PR’s next step and tidies up afterwards. The Done tab shows what Autopilot took off your hands.

heed watches every PR your agents open. Review comments and failing checks go back to the agent that wrote the code, until the PR is green. Where you turn merging on, heed merges the PR too.

When an agent asks for permission, you answer with one key. When a PR needs its next step, a helper takes that step in a split beside your session, never inside it.

04Bigger work

We know you have a favourite harness. Let heed put the others to work.

Plan bigger work with a panel of personas. One persona, the Skeptic, argues against doing the work at all. heed then splits the plan into parts and gives each part to one of your agents, with a lead agent in charge.

Personas also look in on ordinary sessions. They stay quiet until a session has built a lot, then offer a second opinion.

05Memory

heed remembers, so you don’t have to.

heed’s memory is active. It keeps up while you work, and it hands context back when an agent starts.

While a session runs, heed keeps the session’s title current and keeps each decision the agent notes. When a PR opens or merges, heed writes up the work in the memory of its org. The next session in that org starts with that context, and your standup starts from the same memory.

Claude and Codex receive the memory as context. Each org has its own memory, and two orgs’ memories never mix.

Mindmap

Each org gets its own Mindmap of the work. heed feeds the Mindmap back to Claude and Codex.

Standups that write themselves

heed answers your own questions on the days you choose, ready to paste.

Insights

Insights show what the work added up to. History lists each piece of work and how it went.

Full observability

heed receives the OpenTelemetry that Claude Code and Codex send, and shows where time goes, what each model costs and each session’s trace.

Questions, answered briefly

Does it work with my agent?

Claude, Codex, Cursor, pi, opencode and gemini are built in. Any other agent you can run in a terminal works as a custom agent, and heed reads its states from output patterns.

Does it replace my agent?

No. heed runs the agent you already have.

How does it know when an agent is blocked?

heed reads each agent’s hooks, where the agent has hooks, through a small helper command that the agent calls. Where an agent has no hooks, heed watches the terminal and marks the state as a guess.

Will it merge my PRs on its own?

Only where you turn merging on, per PR, repo or org. Merging is off by default. Watching is on by default, because watching only reads from GitHub.

Do I have to use the keyboard?

No, but you will want to. Every command has a key, and ? opens a help overlay in every mode. The mouse works too: every command is in the menu bar and the right-click menus, with its key beside the command.
