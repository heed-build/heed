Run every agent. Ship every PR.

A native macOS app that feels like a TUI, with vim modes and keys. heed runs Claude, Codex, Cursor, pi, opencode and gemini in real terminals, taps you only when one needs you, then feeds review comments and failing checks back to the agent that wrote the code until the PR is green, and merges it by your rules.

Agent states

Whooo needs you?

Every agent reports what it is up to: working, idle, blocked on a permission, asking you a question, done, rate limited. heed gives each its own shape, not only a color, and ga jumps to the next session that needs you. Everything else stays quiet.

  • Agents tell heed through hooks, so it is not guessing.
  • When an agent cannot, heed reads the terminal and marks the state with a dotted ring: a guess, labelled as one.
  • Repo chips carry the org icon and color, so you spot the right session at a glance.

Start work

Say what you want. Skip the setup.

Press o and type the task. heed guesses the repo (or several), names the worktree after the task, picks the agent, and starts it in a real terminal with your prompt. You see the exact command before it runs.

  • It shows its reasoning and a confidence for each guess. Change any of it with one key, or a click.
  • On macOS 26 with Apple Intelligence, Apple’s on-device model picks among the repo guesses and names the branch like your recent ones. Nothing leaves the Mac.
  • Autostart runs the agent inside a shell, so the session outlives the agent.
Agents

Every agent. One perch.

Claude, Codex, Cursor, pi, opencode, or any command you can type. Each one is wired up the way it actually works, and anything heed cannot be told it reads from the screen.

  • Profiles, plan and resume arguments, and how the prompt gets delivered.
  • Hooks are passed per run: your own agent config is never edited.
  • Any command line agent, with output patterns for the states it cannot report.

Goals

Work that outlives a session.

Press gG for Goals: a feature, a migration, a cleanup. Sessions, chats and their PRs belong to a goal, and its GOAL.md says what it is, what it is not and when it is done. Claude and Codex on the goal are told to read it first, and keep it up to date with heed goal.

  • New work finds its goal on its own. When heed is unsure, it asks once, with one key.
  • Items move across a board on evidence: a session, a review, a PR, a merge. A change to what the goal is waits for you.
  • Reviewers score the work against bars that fit the goal. When every criterion and every bar is met, heed marks it done.
Swarms

One goal, a team of agents.

Swarm a goal and a lead agent drafts the plan: phases, tasks, who does each, what waits for what. You change it and approve it; then workers take the ready tasks side by side, each in a worktree of its own, and their pull requests stack and merge in order.

  • Questions go to whoever may answer them: the task next door, heed’s controller for reversible choices, you for the goal, limits and anything destructive.
  • A worker stuck on the same error is told to try another way, then helped. Every step is in the swarm’s steering log.
  • The agents pane and the map show who does what and for how long; a done swarm writes its end-of-build summary.

Get it green

Red PRs come back green.

heed watches the PRs your sessions open: review threads, failing checks, merge conflicts. Each becomes an item for the agent that wrote the code, sent once that agent is idle, with the failed CI log saved where it can read the actual error. gw opens the Watch view: every PR by what it needs, and everything heed did about it.

  • A green checklist per PR: open, ready, no conflicts, required checks passed, threads resolved, no changes requested. heed names the rule that holds it back.
  • Optionally hand merge conflicts and review comments to GitHub’s Copilot coding agent and spare your agent’s tokens.
  • Pause a PR, or a whole selection, for an hour. After three rounds without a new approval heed stops and tells you.
Get it merged

Green PRs land.

Turn merging on per PR with zm, or for a whole repo or org. Each repo gets a merge queue that runs every hour, and whenever one of its PRs turns green. Use GitHub’s auto-merge where its rules are enough, or let heed merge once every rule you set holds. With merging off, heed still says which PRs are ready to merge, and zM merges one now.

  • heed’s rules: green, reviewed after the last push (by a person, or an AI reviewer you trust), quiet for five minutes, your gate checks passed, no hold label, and an optional self-review by a command such as claude -p.
  • M in Repos reads how a repo merged its last 30 PRs and how its CI fails, and proposes the settings, each with its reason.
  • It merges only the commit it checked, brings PRs that fell behind up to date, and comments on the PR saying why it merged.
Worktrees

Worktrees that tidy up after themselves.

Create, list and remove worktrees across repos. Cleanup starts with one honest rule: remove what has been quiet for N days.

  • Never touches dirty or unpushed work, and never pinned sessions.
  • Shows what the next sweep would do before it does it.
  • Org icon and color on every repo, so a long list scans fast.
Resume

Pick up where you left off.

Quit heed, restart the Mac, come back tomorrow. Active sessions reopen with their agent session id, in the same worktrees, tabs and splits. Claude, for example, comes back with --resume.

  • If an agent has forgotten the session, you get a fresh start with the same prompt.
  • Sessions that were mid-turn get a “Continue where you left off.” nudge, yours to change.
  • Running processes are not restored, and heed says so.
Hosts

Agents on other machines, in the same window.

Your devbox, a GPU box, a build machine: heed drives them over the ssh you already have. Press o, pick docs-toolkit @devbox, and the worktree, the agent and its hooks all live there, while you watch from here.

  • Plain OpenSSH: your ~/.ssh/config, your agent, jump hosts. Nothing to run on the host but a small shell script in ~/.heed.
  • With zmx on the host, the agent keeps working when the link drops, and the pane comes back as it was. heed tells you how to install it, and marks sessions without it as not persistent.
  • A remote session shows where it runs: a chip, a rail and a strip in the host’s colour, and the link’s latency.
Attention

Everything that wants you, in one list.

Press gm for one feed: review requests, mentions, failing checks, your open PRs and agents that are waiting. A thread is one row however many reasons it has, and each row says why it is there.

  • Rules in config.toml boost, lower or ignore by team, repo, author or label. Settings shows what an edit would change before you save it.
  • An agent that waits notifies after a short grace, and reminds you once. Nothing notifies in your quiet hours.
  • Pick several items and press s: they become one session with one prompt.
Chats

Ask an agent without a repo.

Press gc to ask an agent something with no repo, worktree or branch. A chat runs in a scratch folder heed makes for it, and has its own group in the sidebar.

  • A chat that is asking or blocked moves to Needs you, like any session.
  • When it turns into work, :promote makes the worktree and hands the conversation to the agent there.
  • With cleanup on, a scratch folder goes 30 days after its chat closes, unless the chat is pinned.
History

See what the work amounted to.

gh lists sessions that ended, and how. T puts them on a timeline by day, L keeps a ledger with a short summary of each piece of work, and D adds up sessions, agent time and PRs over a range.

  • Summaries come from a cheap model, through the agent CLIs you are already logged in to. No API key.
  • The ledger stays after the worktree is gone.
  • :log lists every command and GitHub call heed made, with how long it took and how it ended.

Read the diff, stay put

gd opens committed, staged or unstaged changes over your session. Per file, per commit, or all of it. Ask the agent about a hunk with one key.

Pin the ones that matter

Up to nine pinned sessions, one key each: '1 … '9. Pinned sessions are never cleaned up and always come back after a restart.

Straight talk

A few things we would rather you hear from us.

  • macOS only, and not sandboxed: it has to spawn shells, git and agents.
  • heed does not replace your agent. It hosts it.
  • Agents own their transcripts. heed keeps session records, not conversations.
  • Terminals are libghostty. The ones you already like, with splits and tabs.
  • heed checks GitHub once a day for a new version and asks before installing it. [updates] check = false turns that off.

Questions, answered briefly

Does it work with my agent?

Claude, Codex, Cursor, pi, opencode and gemini are built in. Anything else you can run in a terminal works as a custom agent, with its states read from output patterns.

How does it know when an agent is blocked?

Through each agent's hooks, where it has them, using a small helper command the agent calls. Where it has none, heed watches the terminal and marks that state as a guess.

Will it touch my repos without asking?

Cleanup removes only worktrees that were quiet for N days, never dirty or unpushed work and never pinned sessions, and it can ask before every sweep.

Will it merge my PRs on its own?

Only where you turn merging on, per PR, repo or org; it is off by default. Watching is on by default because it only reads from GitHub. Asking Copilot for help is off until you turn it on too.

Does a goal publish anything?

Only when you mirror it. M puts the goal on GitHub as one issue, with a sub-issue per item, in a tracker repo you choose. Colleagues’ changes there come back as questions for you.

Do I have to use the keyboard?

No, but you will want to. Everything is a key, there is a help overlay on ? in every mode, and the mouse works too: every command is in the menu bar and the right-click menus, with its key beside it.
